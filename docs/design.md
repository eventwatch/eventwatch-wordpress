# 設計の要点

- イベントはカスタム投稿タイプ `eventwatch_event` に保存する。公開・予約・非公開は WordPress の標準どおりで、サイトでの公開は EventWatch の審査を待たない
- 個別ページは `/event/{slug}/`（接頭辞は 設定 › EventWatch で変更可。旧い URL は 301 で転送する）。アーカイブは持たず、一覧はブロックで固定ページに置く
- 欄は EventWatch の主催者の投稿と同じ集合と上限にそろえる（料金・終日は持たない）。日程は保存したときのタイムゾーンの時刻で持ち、一覧で SQL の絞り込みと過去の並べ替えに使う最初の開始・最後の終了を UTC の整数で持つ。開催予定の並びと期間の判定は組ごとに見る（過ぎた回や組の間の期間に左右されないため）
- 表示はサイトの中のデータだけで描く。EventWatch と通信するのは、API キーを設定したときの同期・状態の取り込み・取り込みだけ
- API キーは 設定 › EventWatch か定数 `EVENTWATCH_API_KEY` で渡す。定数を優先する。保存したキーは画面に出さず、自動の読み込みにも載せない
- このサイトを送った別のキーが有効な間、EventWatch はほかのキーの書き込みを 403（`code=siteBoundToAnotherKey`）で断る。ほかの 403 と同じく送信を止めて待ちを残し、案内だけを分ける（古いキーを失効して接続を確かめるか、定期の取り込みが起こす送信が通ると再開する）。この 403 では GET は断られないので、取り込みの GET が通っても案内は消さない。キーの入れ替えは古いキーを先に失効する順になるので、キーを替える欄にもこの順を書く
- サイトごとに乱数のサイト ID と URL を記録する。URL が変わると EventWatch への書き込みを止め、管理者が「複製（新しいサイト ID にして保存したキーを消す。定数のキーは残るので `wp-config.php` から消す）」か「移転（そのまま続ける）」を選ぶまで送らない。記録の URL は 16 進で持つ。平文だと、複製に使う `wp search-replace` や移行ツールの置換で `home` と一緒に書き換わり、違いが消えるため。ハッシュにしないのは、通知に記録の URL を出すため（平文の控えは同じ置換で書き換わる）。読めない値は違うものとして止める。置換を使う本物の移転でも、管理者が選ぶまで止まる
- 送信と結び付けで、サイトの公開 URL（`home` の option）と管理画面の URL も送る。主催者面に送ってきたサイトと管理画面へのリンクを出すため。送る内容のハッシュに入れるので、移転の確認と `home`・`siteurl` の更新の洗い直しで、公開中で送信済みの投稿を送り直す。置換（`wp search-replace` など）は option の更新のフックを通らず、スキームだけの違いは移転の確認も通らないので、最後に洗い直したときの `home`・`siteurl` の保存値（フィルターを通す前の値）のハッシュを覚え、定期の取り込みの 1 回ごとに比べて、違えば洗い直す（送る値で比べると、`WP_HOME` を `is_ssl()` から・`WP_SITEURL` を Host ヘッダーから作るサイトで要求ごとに食い違い、洗い直しが止まらない。記録は平文だと同じ置換で書き換わる。移転の確認を待つ間と止めている間は比べない）。EventWatch は更新日時が同じ要求で審査の状態を変えない。EventWatch が断る形の値・1024 を超える値・ID とパスワード・クエリ・フラグメントを持つ値は、その項目だけ外して投稿は送る。外しても EventWatch の前の値は消えない。管理画面の URL は `siteurl` の option から作る（`admin_url()` のスキームは `is_ssl()` で変わり、フィルターは秘密のパスを返すことがある）。公開 URL と別のホストなら送らない（`WP_SITEURL` を Host ヘッダーから作るサイトで、別のホストの管理画面を記録させない）。管理画面だけ別のホストに置くサイトには、主催者面の管理画面の導線が出ない
- 地図は既定ではリンクだけ。オーナーが Google Maps の API キーを設定したときだけ、詳細に Google マップを埋め込む（閲覧者のブラウザーが Google へ接続する）
- 公式ページの URL は、既定でサイトのイベントのページを EventWatch に送る。別の公式ページがあるときだけオーナーが上書きする
- 最小の版: WordPress 6.7、PHP 7.4
- ブロックを主にし、同じ描画のショートコードを添える
- サイトでの公開・更新・公開の取り下げ・完全な削除を、待ち行列から非同期で EventWatch へ送る。EventWatch での審査は EventWatch での掲載だけを左右する
- 待ち行列は投稿の保護メタの印と、完全な削除の 1 件 1 行の option で持つ。フックでは印だけを積み、送るときに投稿を読み直す。保存の時点で短いタイムアウトで 1 度送り、一時的な失敗だけを WP-Cron で送り直す（1 分・5 分・30 分・2 時間、以後 6 時間ごと。回数の上限なし）。同じ内容は送らない
- 「送らない」にした投稿と公開をやめた投稿は、EventWatch にあれば取り下げる。EventWatch が断る内容（カテゴリなし・オンラインでなく都道府県なしなど）は送らず、編集画面に理由を出す。サイトでの公開は止めない
- 後からキーを入れても、既に公開中のイベントを自動では送らない。キーの保存で全件が審査に並ぶと驚くため。設定画面の「まとめて送る」を押すと、待ち行列に積む。対象は公開中で未送信の、これから開催する投稿で、「送らない」・送れない理由がある投稿・結び付く前の下書きは外す。終了した投稿を外すのは、掲載の役に立たないものが審査に並び、画像の投入の枠を使うため。送りたければ 1 件ずつ更新する
- プラグインの削除で、EventWatch に残る投稿の切り離しを 1 度だけ送る。送れなくても削除は止めない
- アイキャッチ画像はファイルをキーで上げ、返った ID を送る。ファイルの同一性で上げ直しを判定する。保存の時点では上げず、cron で本文と 1 回の要求にまとめて送る
- 画像を上げられなくても本文は送る。前に送った画像があればそのまま残し、編集画面に理由を出す。変換はせず、元のファイルが合わなければ本体が作る縮小版を試す
- 審査の状態は、編集画面を開いたときと 1 時間に 1 回（公開中で最大 30 件、取り込みの古い順）読みに行く。送信の応答にも載るので、送信の直後は読まない。URL の変更を確かめる前は読まない
- EventWatch の Web で作った投稿は、管理画面から選んで取り込める。画像 → 下書き → 結び付け → 公開の順に 1 件ずつブラウザーから進める。画像を欠いたまま結び付けると次の送信で EventWatch の画像が外れるので、入れられなければ作らない。下書きは結び付くまで「送らない」にして、途中で公開されても別の投稿を作らない。やり直しの前に手を入れて公開した内容は、結び付けの後に送る
- 取り込む本文の角括弧は `&#91;` で入れ、ショートコードとして動かさない。本文を書く人はサイトの権限を持つとは限らない。段落と見出しは編集画面で保存すると `[` に戻る
- 取り込んだ内容は送った内容として覚え、そのまま送り返さない。下書きは取り下げの内容として覚え、保存しただけで審査待ちを審査から外さない
- 取り込んだ本文の画像はメディアライブラリへ写し、添付の ID と EventWatch の宛先の対応をメタに持つ。送るときは対応に載る画像だけ元の宛先へ戻す。オーナーが足した画像は EventWatch の投入記録に無いので送らない
- 「気になる」は表示のたびに EventWatch を読まず、掲載中の間だけ持つスラッグのメタを読む。掲載中の判定は審査の状態ではなく、公開面に出ているかで見る
